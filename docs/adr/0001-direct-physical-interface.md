# 通过物理网卡和独立域名解析直连 OKX

日期：2026-10-14（Asia/Shanghai）  
状态：已采用；现作为 `physicalDirect` 网络模式的实现依据。全新配置的默认模式已由 [ADR 0002](./0002-system-network-mode.md) 改为 `system`，本 ADR 不再定义默认值。

本机系统代理与透明隧道会影响 OKX 请求，仅禁用 HTTP 代理仍进入 Fake-IP/utun 路径；绑定物理网卡并独立解析官方域名后，实测拿到两个合约的标记价。因此自用版本通过系统 curl 绑定可用物理网卡，使用有 TTL 的公开 DoH 解析，保留官方域名、SNI 与 TLS 验证，不修改全局网络配置，也不跨交易所替换报价。

这条路径比普通 URLSession 多了网卡选择、DNS 缓存和进程管理成本，并依赖物理网络能够访问所选 DoH 服务；遇到失败应报告网络异常，而不是静默回落到透明隧道。CDN 地址必须动态解析，网络变化与休眠恢复时清理缓存；短期采用系统 curl 是为了复用已验证的直连与 TLS 行为，避免自行实现 HTTP/TLS 协议栈。
