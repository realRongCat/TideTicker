# OKX 系统网络使用 WebSocket 主报价，物理直连保留 REST 采样

日期：2026-10-25（Asia/Shanghai）  
状态：已实现，真实环境验收进行中。

## 背景

现有主报价按 5 / 10 / 15 / 30 秒 REST 轮询。轮询只能观察离散样本，在两次请求之间发生并恢复的短暂触价无法用于穿越提醒；行情快速变化时，菜单栏也可能明显落后。把 WebSocket 生命周期直接加入 `MarkBarAppDelegate` 会继续扩大其中的调度、取消、退避、休眠和迟到结果状态机。

现有网络决定仍然有效：系统网络沿用 macOS 代理、DNS 与路由；物理直连使用 curl、物理网卡绑定、动态 DoH / TTL、官方主机名、SNI 与 TLS 校验。两种模式不得自动互相回退，也不得通过更换地区端点规避 HTTP 403 / 451。

## 决定

建立独立的主报价会话，集中管理关注集合、连接生命周期、严格数据时间推进、重连、同模式 REST 兜底、休眠恢复和迟到结果隔离。应用层消费统一主报价状态，不自行维护每个品种的请求任务、退避或 generation。

OKX 在系统网络模式下使用官方公共 WebSocket 作为主路径：现货订阅最新成交价，USDT 永续与币本位永续订阅标记价。连接中断时立即标记行情连续性不足，并使用系统网络 REST 获取兜底样本；WebSocket 恢复并收到有效新数据后停止兜底。

物理直连模式继续使用现有 curl + DoH REST 采样，不通过系统网络建立 WebSocket。该状态明确显示为 REST 采样和可能漏报，不把新鲜样本解释为连续行情。Binance 与 Bybit 在另行实施其 WebSocket adapter 前继续使用当前网络模式下的 REST 采样。

REST 目录、连接诊断和补充行情仍由 REST 客户端负责。来源切换继续在目录校验与代表报价探测成功后提交。

## 连续性与提醒

报价新鲜度和行情连续性是两个独立维度。过期规则仍为 `max(20 秒, REST 间隔 × 3)`；WebSocket 断线不会提前把旧价标成过期，但会立即标记可能漏报。

WebSocket 断线、REST 采样、切换网络、切换来源、休眠或消费端无法连续处理报价时，穿越类提醒清除旧基准。恢复后的首个有效报价只建立新基准；大于 / 小于仍可按新鲜状态判断。REST 兜底不补发采样间隙中的穿越。

## 代价与边界

系统网络用户获得低延迟主报价，但仍不承诺逐笔行情或交易级告警。代理、网络和交易所都可能造成断线或消息缺口。

依赖物理直连的环境暂时仍是 REST 采样，不获得 WebSocket 的连续性收益。未来如需物理直连 WebSocket，应新增能够绑定物理接口、使用动态解析结果并保持官方 TLS server name 的 adapter；不能把系统网络 WebSocket 偷渡到物理直连模式，也不能关闭证书校验。

WebSocket 重连与 REST 兜底增加长时运行、休眠恢复和故障注入的验证范围。真实通知投递、8 小时常驻、系统网络及三来源矩阵仍是发布门槛，不能以离线测试替代。
