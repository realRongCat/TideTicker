# 默认系统网络，保留可选物理直连

日期：2026-10-16（Asia/Shanghai）  
状态：已实现；真实网络矩阵与公开二进制分发仍需按发布清单验证。

## 背景

[ADR 0001](./0001-direct-physical-interface.md)针对作者本机的 Surge 显式代理与 Fake-IP 透明隧道问题，采用物理网卡绑定、curl 和独立 DoH。该路径在当时网络下可取得报价，但需要物理 IPv4 网络能够直接访问解析服务与交易所。

分享给其他用户后，用户提供了 M2 / macOS 15.5 环境的诊断截图：物理直连请求超时，使用系统 SOCKS 路径的请求成功。该证据来自用户，尚不是开发机复测或新版本远端验收。它说明不能把作者本机的物理直连路径作为所有新用户的唯一连接方式；此前 DMG 打开时的“操作不被允许”属于另一个待定位问题，不能据此归因或宣称已修复。

## 决定

增加全局 `NetworkMode`，提供两个用户可见选项：

| 模式 | 连接方式 |
| --- | --- |
| `system` / 系统网络 | 原生 URLSession 使用 macOS 默认代理、DNS 与路由。HTTP / HTTPS / SOCKS / PAC 按系统配置处理；不固定使用 `1.1.1.1`，不强制绑定物理 IPv4 网卡。 |
| `physicalDirect` / 物理直连 | 保留 ADR 0001：系统 curl 显式禁用代理、动态选择物理网卡、通过 DoH 获取官方域名地址并按 TTL 缓存，保持官方主机名、SNI 与完整 TLS 校验。 |

两种模式均访问同一来源的官方公共 API。应用不修改系统代理、DNS 或 Surge 设置，不自动选择代理节点。失败保留所选模式及具体错误，不在两种模式间自动回退；HTTP 403 / 451 不通过换来源、地区端点、地址、网卡或代理出口规避。

## 默认值与兼容性

- 全新配置的 `TidePreferences.networkMode` 默认为 `system`。
- 已保存 JSON 缺少 `networkMode` 时解码为 `physicalDirect`，保留升级前行为。已有关注、常驻位置、提醒和重复间隔不因迁移改变。
- 网络模式是全局连接偏好。来源 profile 的恢复沿用当前模式，不能用该 profile 中历史保存的模式覆盖用户当前选择。
- 用户在“行情来源 → 网络连接”中手动选择，选择立即保存并重连。“测试连接”的结果显示正在使用的模式。
- 旧版升级后若需要沿用系统代理，应主动选择系统网络；升级本身不会静默改变旧用户的请求路径。

## 切换与异步隔离

目录、主报价、补充行情和连接测试统一使用当前模式。模式改变时取消旧请求并替换传输客户端，通过 generation / request ID 拒绝迟到的结果与任务清理。休眠期间保存选择，唤醒后使用新模式。自 [ADR 0003](./0003-main-quote-session.md) 起，系统网络下的 OKX 主报价以 WebSocket 为主并在断线时使用同模式 REST 兜底；物理直连仍使用当前模式的 curl / DoH REST 采样，不借用系统网络 WebSocket。

保留上次已知报价，仍按原数据时间计算过期，不能把重新连接当作数据刷新。穿越类提醒清除前值基准，在下一个有效新报价上重新建立；大于/小于按新鲜状态重新判断。规则的实际冷却记录保留，重连间隙的穿越不补发。

## 代价与边界

系统网络能够沿用用户现有代理，但也会受系统路由、DNS、PAC 与代理本身的可用性影响。URLSession 采用系统默认行为不等于每种代理或网络已逐一验收。物理直连仍有独立 DoH 与 IPv4 物理网络要求，由用户按环境选择。两种模式都不能保证交易所在任何地区可用。

## 验证边界

离线传输测试、偏好迁移和本机构建不能证明任意代理、网络或地区均可访问交易所。系统 HTTP / HTTPS / SOCKS / PAC、物理直连、三来源、休眠恢复和登录启动必须在目标环境分别验证。公开二进制还需 Developer ID 签名和 Apple 公证；完整门槛见 [Release checklist](../RELEASE_CHECKLIST.md)。
