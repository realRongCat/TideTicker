# TideTicker 使用指南

TideTicker 是一款原生 macOS 菜单栏行情观察工具。它无需交易账户或 API Key，不提供交易和下单能力。

[返回项目首页](../README.md) · [查看更新记录](../CHANGELOG.md) · [问题反馈](https://github.com/realRongCat/TideTicker/issues)

## 安装

### 系统要求

- macOS 13 或以上。
- Universal 安装包同时包含 Apple Silicon（arm64）和 Intel（x86_64）版本。
- Intel 架构已完成编译验证，Intel 真机运行仍待验证。

### 下载与校验

1. 打开 [GitHub Releases](https://github.com/realRongCat/TideTicker/releases/latest)。
2. 在 **Assets** 中下载 `TideTicker-<版本>-universal.dmg` 和同名的 `.sha256` 文件。
3. 在终端进入下载目录并校验文件：

   ```sh
   cd ~/Downloads
   shasum -a 256 -c TideTicker-*-universal.dmg.sha256
   ```

   看到 `OK` 后再继续安装。若校验失败，请删除文件并从官方 Release 重新下载。

4. 打开 DMG，将 `TideTicker.app` 拖入其中的 **Applications** 文件夹，复制完成后弹出磁盘映像。
5. 从“应用程序”启动 TideTicker。它只显示在菜单栏，没有 Dock 图标。

### 首次启动

当前公开安装包使用 ad-hoc 签名，尚未经过 Apple 公证。macOS 可能在首次打开时拦截应用。

确认安装包来自本仓库且校验通过后，先尝试打开 TideTicker，再前往“系统设置”→“隐私与安全性”，找到 TideTicker 的拦截提示并选择“仍要打开”。随后按系统提示确认。请勿使用移除隔离属性或关闭 Gatekeeper 的命令。

若系统明确提示应用包含恶意软件或文件已损坏，请停止使用并[提交问题](https://github.com/realRongCat/TideTicker/issues)。Apple 的相关说明见[安全地打开 Mac 上的 App](https://support.apple.com/102445)。

### 从源码构建

源码构建需要支持 Swift 6 的 Xcode 或 Command Line Tools：

```sh
git clone https://github.com/realRongCat/TideTicker.git
cd TideTicker
bash scripts/build-app.sh
open dist/TideTicker.app
```

测试、Universal 构建和贡献说明见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 开始使用

全新配置默认使用 OKX 和系统网络，并在菜单栏常驻 BTC、ETH 的 USDT 永续标记价。

1. 点击菜单栏报价，选择“显示主窗口”。
2. 在“关注品种”中从交易所官方目录选择市场，并设置最多两条菜单栏常驻报价。
3. 在“行情来源”中选择交易所和网络模式，按需开启补充行情。
4. 在“到价提醒”中允许系统通知并创建规则。

关注列表最多保存 20 个品种，菜单栏最多常驻两条。常驻行始终显示图标、币种和主报价；补充行情只出现在展开菜单和主窗口。

“登录时启动”可在应用菜单中设置。若 macOS 显示“待系统批准”，请在系统设置的登录项中确认。

## 行情与显示

### 市场口径

| 市场 | 主报价 | 报价币 | 结算币 |
| --- | --- | --- | --- |
| USDT 现货 | 最新成交价 | USDT | USDT |
| USDT 线性永续 | 标记价 | USDT | USDT |
| USD 币本位永续 | 标记价 | USD | 标的币 |

同一币种可以同时存在于现货和永续市场。添加关注和提醒时，请核对交易所、完整合约名称和价格口径。

### 补充行情

“显示补充行情”使用一个总开关：

- 关闭时，所有卡片只显示主报价。
- 开启时，现货增加 24 小时涨跌；永续增加 24 小时涨跌、资金费率、距下次结算时间和同所现货溢折价。

永续溢折价只使用同一交易所、同一币种且同一报价币的现货价格。参考现货不会加入关注列表，也不会参与提醒。USD 币本位永续目前没有同报价币参考现货，因此不显示溢折价。

补充行情约每 60 秒刷新。补充字段暂时不可用时，不影响主报价继续更新。

### 报价状态

TideTicker 分别显示价格是否过期和行情是否连续：

- **过期**表示当前展示的是上次已知价格，不能视为实时价格。
- **可能漏报**表示两次 REST 采样之间、WebSocket 断线、系统休眠或恢复期间可能错过短暂触价。
- 恢复连接后，穿越类提醒先用新报价重新建立判断基准，不补发空档期间无法确认的穿越。

## 行情来源与网络

一次只能使用一个行情来源。OKX、Binance 和 Bybit 分别保存各自的关注列表、常驻位置和提醒；切换回来时会恢复该来源的配置。

| 模式 | 行为 | 适用情况 |
| --- | --- | --- |
| 系统网络 | 沿用 macOS 的代理、DNS 和路由 | 默认选项，适合大多数用户 |
| 物理直连 | 禁用代理，绑定物理网卡，并使用独立 DNS-over-HTTPS | 明确需要绕开本机代理链路的环境 |

OKX 在系统网络下使用 WebSocket 接收主报价，断线时使用同模式 REST 兜底。Binance、Bybit 和物理直连模式使用 REST 采样，因此会明确标记“可能漏报”。应用不会自动切换交易所、网络模式或地区端点。

连接异常时，在“行情来源”→“网络连接”中确认当前模式并使用“测试连接”。HTTP 403、451 等服务端拒绝会原样显示；TideTicker 不绕过交易所的访问限制。

从早期测试版本升级时，旧配置可能继续使用物理直连。如希望沿用 macOS 已配置的代理和 DNS，请手动改为“系统网络”。

## 到价提醒

提醒始终绑定到具体交易所和具体合约。系统通知标题会写明交易所、原生合约、价格口径、条件和阈值，便于区分现货与永续。

| 条件 | 触发方式 |
| --- | --- |
| 上穿 | 价格从阈值下方到达或超过阈值 |
| 下穿 | 价格从阈值上方到达或低于阈值 |
| 穿越 | 向任一方向穿过阈值 |
| 大于 | 当前新鲜价格严格大于阈值 |
| 小于 | 当前新鲜价格严格小于阈值 |

上穿、下穿和穿越需要先观察到阈值一侧的有效价格来建立基准。大于和小于按当前新鲜价格判断，创建后可以在下一条有效报价触发。

选择“需确认”后，每条规则只发送一次系统通知，并在菜单和提醒页保留待确认状态。规则再次满足时会更新最新价格和时间，但不重复发送通知；点击“确认”后，该规则重新布防。

若通知权限未开启，规则不会被消耗。请在提醒页选择“允许通知”，或前往“系统设置”→“通知”检查 TideTicker。

> [!CAUTION]
> 到价提醒只用于辅助观察。网络、代理、REST 采样、WebSocket 断线、系统休眠、交易所异常和本机处理延迟都可能造成漏报，不能替代交易所风控或止损。

## 版本更新

“自动检查更新”默认开启，定期查询 TideTicker 的最新稳定版 GitHub Release。发现新版本时，菜单栏会显示非抢焦点提示；你可以打开发布页、24 小时后再提醒或跳过该版本。

也可以从菜单中选择“检查更新…”。“关于 TideTicker”显示当前安装的版本和构建号。

TideTicker 只打开经过校验的官方 Release 页面，不会自行下载或替换应用。关闭自动检查后，手动检查仍可使用。

## 数据与隐私

关注列表、显示偏好、网络模式和提醒规则保存在本机。TideTicker 不包含分析或遥测，也不会把关注列表或提醒阈值发送到 TideTicker 服务器。

应用会访问当前交易所的公共行情接口；物理直连模式还会访问 Cloudflare 的公共 DNS-over-HTTPS 服务。更新检查会访问 GitHub 公共 API。完整边界见 [PRIVACY.md](../PRIVACY.md)。

## 常见问题

### 启动后为什么看不到窗口？

TideTicker 是菜单栏应用，没有 Dock 图标。点击菜单栏中的报价，再选择“显示主窗口”。

### 为什么价格变灰或出现感叹号？

这表示报价已经过期或当前连接存在错误。打开主窗口查看状态，并到“行情来源”中测试连接。

### 为什么补充行情没有显示？

确认“显示补充行情”已开启，并等待下一次补充行情刷新。部分字段只适用于永续，币本位永续目前不显示同报价币溢折价。

### 为什么没有收到系统通知？

先在“到价提醒”页确认通知权限。若规则要求确认并已有待确认事件，需要先点击“确认”才会重新布防。连接中断或报价过期期间无法保证触发。

### 如何彻底退出？

点击菜单栏报价，在菜单底部选择“退出 TideTicker”。关闭主窗口不会退出菜单栏应用。
